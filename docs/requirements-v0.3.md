# RAGポートフォリオ 統合定義書 v0.3

作成日: 2026-08-04
PM: クリーデ ／ 承認: ショウゴさん

## 目的

副業参入用ポートフォリオ第一号。実用ではなく「業務文書をAIに扱わせる際の意思決定を見せる」ケーススタディ。完成速度を最優先する。

## 成果物（3点）

1. 公開GitHubリポジトリ（動くCLIツール）
2. README＝ケーススタディ本体（設計判断・棄却経緯・失敗分析を記述）
3. 評価記録：想定質問10問の検証ログ（JSONL）

## 機能要件

### v1（先行完成）
- ingest：公開仕様書PDF1冊 → 突合抽出 → 条文構造単位のチャンク分割 → ローカルベクトルDB格納
- query：質問 → 検索 → LLM生成 → 出典（章・条番号）付き回答

### v1.1（MinerU拡張）
- ingestに抽出エンジン第4枠としてMinerUを追加（エンジンは差し替え可能な枠、という構成を維持）
- 素材はスキャン帳票のサンプル1〜2枚（公開文書から選定。点検様式に近いものが理想）
- 完成条件は「帳票の表構造がMarkdown/JSONで抽出でき、チャンクとして検索に載ること」の実演のみ。10問評価はしない
- 図面（CAD系）はスコープ外。文書系ツールでは未解決領域であり、期待値を帳票・表までに置く

## 非要件（やらないこと）

UI／複数文書横断／文書更新の同期／v1でのOCR（テキスト層PDFを選定）／運用自動化／図面からのデータ抽出

## 素材

- v1：国交省「土木工事共通仕様書」等の公開文書から1冊（ショウゴさん選定）
- v1.1：公開のスキャン帳票サンプル1〜2枚（ショウゴさん選定）

## プロダクト構成（確定）

| 工程 | 採用 | 備考 |
|---|---|---|
| PDF抽出（v1） | pdfplumber＋PyMuPDF 突合 | 既存の突合スクリプトの設計を流用 |
| PDF抽出（v1.1） | MinerU hybridバックエンド | RTX 5060 Ti 16GBでVRAM要件（8GB）を充足 |
| チャンク分割 | 自前ルールベース（条番号正規表現） | ドメイン知識の見せ場 |
| フレームワーク | LlamaIndex | 検索主目的の定番 |
| ベクトルDB | Chroma | ローカル・無料 |
| 埋め込み | ruri-v3-310m | 日本語SOTA。プレフィックス必須（仕様書§3参照） |
| 生成 | Claude API | キーは環境変数管理 |

## 棄却リスト（READMEに理由ごと記載）

- tesseract：日本語で実用不達（実試行済み）
- Docling：日本語の文字誤抽出報告（漢数字・長音記号等）
- YomiToku：精度は最高クラスだがCC BY-NC-SA（商用は別途ライセンス）。商用ライセンス交渉が可能な案件では再検討候補
- ハイブリッド検索・RAGAS：10問規模に過剰。将来改善候補として記載

## 完成条件

- v1：評価10問中7問以上でpass（出典正・原文と矛盾なし）。精度の追い込みはせず、未達分は失敗分析としてREADMEに書く
- v1.1：帳票1〜2枚の構造化抽出と検索ヒットの実演
